# Mai30 scaled Wright–Fisher MSRC pilot

Status: **BLOCKED for completion of all 12 primary 500-tree collections by
local runtime.** Six collections completed with 25 histories × 20 loci; the
remaining six retain one validated history each. The partial outputs are
usable for workflow checks, and the resumable command remains available for
cluster completion.

## Design

The pilot uses the four previously validated no-outgroup Mai D1 replicates,
retaining their identifiers and observed original mean normalized RF values:

| ILS label | condition / replicate | original mean normalized RF |
|---|---|---:|
| low | `outgroup.0.species.1.5.genes.1.5 / 042` | 0.004 |
| moderate | `outgroup.0.species.5.genes.5 / 005` | 0.303 |
| high | `outgroup.0.species.1.5.genes.1.5 / 074` | 0.579 |
| extreme | `outgroup.0.species.1.5.genes.1.5 / 007` | 0.979 |

The four species trees are fixed Mai backbones. Each MSRC condition uses 25
independent Wright–Fisher rearrangement histories, with 20 loci per history.
The resulting 500-locus collection retains `history_id` and `locus_id` in
`locus_history_mapping.tsv`. The primary initial arrangement frequency is 0.5;
parallel `freq_0.2` configurations are prepared as a sensitivity set and are
not part of the primary production run.

The three MSRC treatments are cross-arrangement recombination fractions 1.0
(no suppression), 0.5 (moderate), and 0.1 (strong). The direct scaled MSC
controls are generated separately with the same species trees and demographic
scaling.

## Scaling and demographic conversion

The original SimPhy sizes are haploid. The validated mapping is

\[
N_e^{\mathrm{MSRC}}=N_H^{\mathrm{SimPhy}}/2.
\]

The computational transformation is `N_scaled = round(0.001 * N_e)` and
`g_scaled = 0.001 * g`. Exact values, integer values, and relative rounding
errors are written to every YAML configuration. For the four selected
replicates, the scaled sizes are 457, 34, 457, and 139, respectively; the
largest relative integer-size error is about 1.38% for replicate 042. The
branch lengths retain the scaled Mai topology and ultrametricity.

This transformation preserves neutral coalescent-unit branch lengths in the
continuous approximation. It does not preserve finite-copy drift,
rearrangement persistence, recombination dynamics, origin probabilities, or
selection behavior exactly. The outputs must therefore be described as a
scaled WF approximation rather than an original-scale reproduction.

|---|---:|---:|---:|

## Pilot outputs and ASTRAL

The resumable WF runner is
`analysis/scripts/run_scaled_wf_pilot.py`. It validates every 20-tree history,
checks all taxon sets and coalescence counts, and combines histories only after
validation. ASTRAL-IV v1.25.4.8 is invoked with `--length CULength` and the
same settings for MSC and MSRC collections by
`analysis/scripts/run_astral_scaled_pilot.py`.

The current per-collection topology and branch-length table is
`analysis/results/mai30_scaled_wf_astral.tsv`. The branch-length error columns
separate common true/inferred splits from topology error; they are not
interpreted as branch estimates on incorrectly recovered splits.

Six MSRC collections currently contain 500 trees: all three treatments for
replicates 007 and 042. The other six MSRC collections contain one validated
20-tree history each. The direct MSC controls contain 500 trees each.

The preliminary figure is generated by
`analysis/scripts/plot_scaled_wf_pilot.py` and saved as
`analysis/figures/mai30_scaled_wf_pilot.png` after the 25-history collections
are available. Because the current figure includes six 20-tree smoke
collections, it is a workflow figure and must be regenerated after cluster
completion.

## Runtime and feasibility

The existing benchmark estimated about 1,111 seconds for 500 loci at the
representative `c=0.001` history when run serially. The first 20-locus
30-taxon MSRC smoke history took approximately one minute including simulator
startup. The production runner uses four workers, writes per-history logs, and
can be restarted after interruption. The original-scale forward WF model
remains computationally infeasible under the current generation-by-generation
implementation. Completed 25-history collections required about 1,600–2,013
seconds of summed history runtime for replicate 042 and 96–112 seconds for
replicate 007. Four workers were saturated. The full primary pass was
interrupted after 156 of 300 histories completed; no completed history failed
validation.

## Remaining limitations

The primary pilot uses established intermediate-frequency structural
variation (`initial_frequency=0.5`), not a de novo single-copy origin. Loss,
fixation, and segregation remain stochastic outcomes; no terminal pattern is
imposed. The 500 loci are pooled across 25 shared-history blocks, so uncertainty
across histories must be retained in later inference. The 0.2-frequency
sensitivity set has been prepared but should be run only after the primary
comparison is complete. The SLURM template is
`cluster/run_scaled_wf_pilot.slurm`; rerunning the pilot command reuses
completed histories and fills missing ones.
